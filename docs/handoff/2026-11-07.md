## 关键结论（细节与数字见各 README）

1. 17 字段（echtvar 主场）：echtvar 墙钟 18s 对 immkv 窄库 30s；immkv
   CPU 省 2.6 倍。
2. 540 数值（10G 生产预算）：反转——完整输出 immkv 快 ~1.25 倍墙钟、
   11 倍 CPU；无输出纯查询快 ~9 倍墙钟、12 倍 CPU。
3. 568 全字段：echtvar 在 10G 下任何并行度（4/2/1 进程）都被 OOM 杀死
   （无限制时单进程峰值常驻 24.1GB，字符串字典驻留堆内）；immkv 以
   3.9GB 常驻 5 分钟完成，全部字符串值逐字节一致。
4. echtvar 的两个实测缺陷：浮点量化振幅上限（|v|>1073 时 ×2e6 溢出
   i32，静默编成缺失，两实验共 808 条实证）；字符串字典在真实 gnomAD
   上退化为逐值存原文（chr22 上 vep 有 305 万唯一值）。

## immkv_anno 立项备忘（API 已与用户定稿）

- 子命令：build / annotate / info / get；CLI 旗标与语义见对话定稿：
  build（-o/--outdir、-p/--prefix 默认 IMMKV、-f/--field-list 支持逗号
  或 @file、-t 默认 2=并行染色体数、--pack-kb、--chrom 只能缩）；
  annotate（-i 支持 stdin、-d、-o 默认 stdout、-O v|z、-l 默认 1、
  -f、-p、--raw-database-metadata、-t 默认 4、-b 4096、--dry-run）。
- 库自描述：build 写 .vcf.header + manifest.json；annotate 打开时找
  .vcf.header，找不到且无 --raw-database-metadata 即报错；输出键
  （前缀_字段）与查询表头 INFO ID 求交集，撞车点名报错、无 --force、
  只追加永不覆盖；输出前补 ##INFO 声明（合规 VCF）。
- v1 边界：单库；VCF 进（文本/gz/bgz 按魔数）VCF 出；BCF 靠管道；
  BED/GFF 区间库留给 v2（引擎 Scan/GetPrefix 已够，缺的是工具层）；
  不需要输入索引但要求坐标有序（逐行校验）。
- test/ 代码即 immkv_anno 的性能依据与演化起点：annotate/buildnarrow/
  buildfull 直接搬，增量是 CLI、头部声明、bgzf 输出、sidecar、缺元数据
  拒跑。输出端优化清单（写出不污染缓存、并行压缩级别 1、值内字段目录、
  少一次拷贝、stdout 流式）在对话里已列，优先级前两条最高。
- 随机查询用 OpenEager 点查句柄（内存索引 ~65MB + 1.5KB 微块 pread +
  cacheMB 解压缓存），不是整库载入；乱序查询对照实验（echtvar mmap
  随机 vs immkv 点查）未做，可作为 immkv_anno 时代的第一个实验。
